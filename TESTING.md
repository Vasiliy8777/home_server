# Проверки проекта

## Общая проверка

Требуются Java 21 и Node.js 20+:

```powershell
.\gradlew.bat check --offline
```

`check` запускает Java-тесты через JUnit 5 и тесты фронтенда через встроенный
Node.js test runner. npm-зависимости и установка node_modules не нужны.
`--offline` подходит при наличии зависимостей Gradle в локальном кеше;
для первой загрузки зависимостей этот параметр нужно убрать.

Отдельные наборы:

```powershell
.\gradlew.bat test --offline
npm test
```

## Что проверяется

- Java: загрузка, переименование и удаление файлов, пагинация, фильтрация служебных
  каталогов, нормализация путей и запрет `..`; создание, хранение, отключение,
  удаление публичных ссылок, границы папки и права доступа.
- JavaScript: CSRF и маршруты публичного API, скачивания и отмена, чанки загрузок,
  сессии папок, устаревшие ответы, очередь метаданных с ограниченным параллелизмом
  и повторами, lifecycle наблюдателей / viewer / polling, прогресс и история передач.
- CSS/HTML: структура правил, переменные темы, приоритет скрытых модалок,
  reduced-motion и возможность браузерного масштабирования.

Java-тесты работают с временными папками. Они не запускают сервер и не обращаются
к настоящему хранилищу, SSL-сертификатам или пользовательским настройкам.
Node-тесты исполняют настоящий `app.js` с небольшими подменами DOM, таймеров
и fetch; браузерную верстку они не моделируют.

## Проверка в настоящем браузере

```powershell
npm run test:browser
```

Скрипт ищет установленный Chrome / Edge / Chromium. Другой путь можно указать:

```powershell
$env:BROWSER_PATH = 'C:\path\to\chrome.exe'
npm run test:browser
```

Это headless-проверка настоящих index.html / share.html, app.js и style.css
при ширинах окна 1280 и 390 пикселей. Проверяются карточки, модалки, просмотр
изображения, выделение и интерфейс прав публичной ссылки. Сетевой API подменён
фиксированными ответами. Внешние CDN-скрипты исключены; работа Plyr / Hls.js
и ffmpeg этим тестом не проверяется. Артефакты и изолированные профили браузера
создаются в `build/browser-smoke`.

## Ограничения

Это регрессионные и smoke-тесты, а не полное end-to-end покрытие HTTP-сервера.
SSL, аутентификация через реальный сервер, загрузки больших файлов по сети,
Windows junction / symlink и реальная HLS-конвертация требуют отдельных
интеграционных проверок. Замеры FPS, памяти и нагрузки GPU не выполняются.
Большие скачивания контролирует браузер; небольшие скачивания при повторном
запуске начинаются с нуля, поскольку полученные байты не сохраняются между сессиями.
