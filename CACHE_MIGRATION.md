# SQLite и оптимизация кеша

После обновления сервер использует SQLite для карточек папок, метаданных,
описаний ИИ и поисковых векторов. Фото, видео, миниатюры и HLS остаются файлами.

## Применение

1. Завершите или остановите текущую индексацию и загрузки.
2. Перезапустите сервер с обновлённым кодом.
3. Откройте галерею. Каталог создастся автоматически; готовые карточки/метаданные
   импортируются из старых JSON при первом обращении к соответствующей папке/файлу.

Описание ИИ импортируется при запуске поиска: валидные записи текущей модели
попадают в SQLite без вызова Ollama. Изображения для этих записей остаются по
существующим путям. Первый запуск может занять больше времени из-за импорта.
Последующие старты читают записи из БД; векторы сохранены как бинарный float32.
Поиск по смыслу пока сравнивает векторы в памяти; отдельный индекс ближайших
соседей не добавлялся.

## Настройки

```yaml
app:
  cache:
    database-enabled: true
    database-path: C:/Users/Vasiliy/AppData/Local/homeserver/cache/catalog.sqlite
```

В `application.yml` путь по умолчанию определяется через `LOCALAPPDATA` и
указывает на SSD `C:` этого компьютера. Переменные среды:

- `APP_CACHE_DATABASE_ENABLED` — включить SQLite; по умолчанию `true`.
- `APP_CACHE_DATABASE_PATH` — полный путь к локальному файлу БД.

SQLite работает в WAL с `synchronous=FULL`; операции БД сериализуются одним
подключением, чтобы ограничить запись. Файл должен находиться на локальном диске.
Рядом создаются файлы `catalog.sqlite-wal` и `catalog.sqlite-shm`.
Для резервной копии остановите сервер и копируйте БД; не копируйте только основной
файл живой WAL-базы без корректного механизма резервного копирования.

Старые JSON не удаляются при импорте. Установив
`APP_CACHE_DATABASE_ENABLED=false` и перезапустив сервер, можно использовать
прежний файловый кеш. Новые описания/метаданные после переключения на БД не
дублируются обратно в старые JSON: поэтому отключение SQLite не переносит туда
новые записи. Саму БД нужно сохранить, чтобы продолжить использовать их позже.

## Изменения в работе

- При промахе кеша папка перечисляется один раз вместо повторения обхода для
  каждого блока из 200 файлов.
- Обычная галерея получает страницы по 100 карточек из SQLite. Задача не
  удерживает все эти карточки в памяти. Старые поколения каталога сохраняются
  пока используются открытыми задачами пагинации.
- При сортировке по имени/размеру без фильтров первая страница доступна до
  завершения чтения EXIF. Сортировка по дате и группировка с периодом ждут
  полных метаданных, чтобы не выдавать неправильный порядок.
- Подготовка папок ограничена двумя одновременными операциями; пул метаданных
  общий. Частые фоновые обновления одной папки объединяются с задержкой 500 мс.
- Завершённые задачи удаляются после 15 минут без обращений; хранятся максимум
  32 завершённые задачи. Очень старую открытую папку может потребоваться открыть
  заново. Общая очередь задач ограничена 96 заданиями.
- В памяти сохраняются максимум 10 000 наборов метаданных и 256 статистик папок.
  Размер/дата проверяются при обращении к метаданным. Статистика обновляется
  после инвалидации или через 30 секунд.
- Статистика не обходит `HiddenPaths` и не собирает всё дерево путей в память.
- Прогресс общего кеширования записывается не чаще раза в секунду во время
  работы; остановка и завершение сохраняются сразу.
- Новые загрузки используют чанки 4 МиБ. Возобновление берёт размер из сессии,
  поэтому ранее начатые загрузки с 1 МиБ сохраняют свои границы чанков.
- Upload использует общий для приватных/публичных маршрутов lock по сессии,
  потоковый буфер 64 КиБ, проверку размера чанка/итогового файла и атомарную
  замену JSON состояния. Состояние upload пока хранится в JSON, а не в SQLite.
  Временный файл остаётся на томе оригиналов, чтобы избежать лишнего копирования.

Оригинальные файлы и права публичных ссылок обслуживаются существующими маршрутами.
БД — каталог/кеш, а не место хранения оригиналов.

## Практические ограничения

Проверка актуальности папки всё ещё использует её сигнатуру и перечисление
детей. После изменений сохраняется новое поколение карточек папки; обновление
одной отдельной строки без пересборки, WatchService и курсорная пагинация могут
стать следующими улучшениями. Размерная сортировка использует поле размера из
JSON строки БД. Нельзя обещать конкретную скорость без замеров на коллекции.

## Проверки

```powershell
.\gradlew.bat check --offline
npm run test:browser
```

Проверяются миграция JSON, страницы/сортировка SQLite, стабильность открытого
поколения при обновлении, ранняя выдача до метаданных, сохранение поиска ИИ без
повторного анализа, актуальность метаданных, объединение обновлений, исключённые
папки, потоковые чанки и совместимость возобновления.
