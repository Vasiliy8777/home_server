# Локальная генерация музыки

`muz_gen` в панели облака открывает генератор музыки. Доступ требует входа в облако;
публичные ссылки не предоставляют доступ к заданиям, промптам или аудио.

## Хранение

Модели, код ACE-Step и окружение Python находятся на SSD в `C:\AI\muz_gen`:

| Путь на SSD | Содержимое |
| --- | --- |
| `models` | Общий комплект моделей ACE-Step, включая XL |
| `runtime/ACE-Step-1.5` | Код движка и Python-окружение `.venv` |
| `runtime/bootstrap` | Инструменты установки |

Промпты, промежуточные файлы и песни остаются в `K:\muz_gen`:

| Путь | Содержимое |
| --- | --- |
| `song-<UUID>.wav` | Результаты после нажатия «Сохранить» |
| `tmp/<UUID>/result.wav` | Временные результаты, доступные для прослушивания |
| `tmp/<UUID>/ace-result.json` | Фактические параметры результата, включая seed и выбранную модель |
| `tmp/ace-step` | Внутренние промежуточные файлы ACE-Step |
| `music-prompts/<UUID>.txt` | Отправленные описания музыки |
| `lyrics-prompts/<UUID>.txt` | Исходные запросы на создание текста |
| `lyrics/<UUID>.txt` | Созданные тексты песен |
| `lyrics/<UUID>-input.txt` | Текст, переданный для создания аудио |
| `jobs/<UUID>.json` | История, настройки, состояние задания и ссылка на сохранённый файл |
| `sources/<UUID>` | Оригинал аудиообразца, нормализованный WAV, его параметры и журналы проверки |
| `tmp/ace-step/cloud-inputs/<UUID>.wav` | Рабочая копия образца для задания ACE-Step |
| `runtime/start-music.ps1` | Скрипт автоматического запуска движка на SSD |
| `cache`, `logs` | Кэши обработки, история движка и журналы |

Внутренний каталог `.cache` ACE-Step направлен через junction в `K:\muz_gen\cache\ace-runtime`,
поэтому внутренние задания с промптами также сохраняются на K:.
После миграции старые пути `K:\muz_gen\models`, `K:\muz_gen\runtime\ACE-Step-1.5`
и `K:\muz_gen\runtime\bootstrap` служат ссылками на SSD для совместимости старых команд.

Имена файлов не зависят от введённого пользователем текста. Служебная папка `muz_gen`
исключена из обычного обхода файлов через `HiddenPaths`. Готовые песни доступны в истории генератора.
Кнопка «Скачать» у открытого результата скачивает WAV на текущее устройство.
Она доступна для временных и сохранённых песен, включая результаты, открытые из истории.
Промпты и история сохраняются после удаления временного аудио; сохранённую песню кнопка удаления временного файла не удаляет.
Ollama использует свою существующую библиотеку моделей.

## Установка

PowerShell из корня проекта:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts\setup-music.ps1
python scripts\verify-music-models.py --root C:\AI\muz_gen\models --hash
```

Скрипт установки можно повторять: Hugging Face использует уже скачанные файлы.
Он устанавливает ACE-Step в отдельное окружение Python 3.12, основной комплект,
XL Turbo и Qwen3 14B в Ollama. Для установки требуется интернет.
Параметр `-EngineRoot` скриптов установки и запуска меняет каталог моделей и Python
(по умолчанию `C:\AI\muz_gen`), `-Root` меняет каталог данных (по умолчанию `K:\muz_gen`).
Установщик сохраняет выбранный путь движка в `K:\muz_gen\runtime\engine-location.json`;
автоматический запуск использует его без изменения настроек Java-сервера.

## Запуск

После установки кнопка `start` автоматически запустит локальный движок при необходимости.
Для ручного запуска или диагностики:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts\start-music.ps1
```

Движок слушает только `127.0.0.1:8001`. По умолчанию включён offline-режим,
модели загружаются в память при первом задании. Для первого запуска нужны все веса.
Включены CPU offload, PyTorch backend, один GPU worker и переключение моделей по запросу.
Для RTX 4070 выбран профиль 12–16 ГБ (`MAX_CUDA_VRAM=12.001`): фактические 11.994 GiB
и даже ровно 12 GiB движок относит к младшему диапазону и подменяет LM 1.7B на 0.6B.
Это только выбор профиля; физическая видеопамять не увеличивается, CPU offload включён.
При переносе на другую видеокарту этот параметр нужно пересмотреть.
Режим XL на RTX 4070 12 ГБ требует особенно много ОЗУ и времени на загрузку.
Перед генерацией приложение выгружает загруженные модели Ollama; генерация текстов
отправляется с `keep_alive: 0`. Другие GPU-процессы и AI-индексацию фотографий/видео
нужно остановить перед генерацией. Скрипт не останавливает чужие процессы.

Облако запускается обычным способом. После изменения Java/HTML требуется его перезапуск.
Кнопка открывает форму: описание, текст/запрос для текста, язык, длительность, BPM,
модель, инструментальный режим, музыкальное планирование, автоматическое уточнение,
seed и число шагов. Для Turbo рекомендуется 8 шагов. Автоматическое уточнение
может изменить описание, поэтому изначально выключено.

История показывает последние 50 заданий. Закрытие окна не прерывает генерацию.
После перезагрузки страницы активное задание восстанавливается через историю.
После перезапуска самого Java-сервера незавершённые задания помечаются как прерванные;
ACE-Step может продолжать старое задание — проверьте его журнал перед повторным запуском.
Автоматического удаления временных результатов нет: они остаются до явного удаления
или сохранения. Тексты и настройки не удаляются автоматически.

Настройки приложения задаются через `APP_MUSIC_ROOT`, `APP_MUSIC_ACE_URL`,
`APP_MUSIC_OLLAMA_URL`, `APP_MUSIC_LYRICS_MODEL`, `APP_MUSIC_TIMEOUT_SECONDS`.
Автоматический запуск управляется `APP_MUSIC_AUTO_START` (по умолчанию включён).
Адреса музыкальных сервисов допускают только локальный HTTP.

## Музыка по звуковому образцу

В окне `muz_gen` выберите режим:

- **Новая песня по описанию** — обычная генерация без образца.
- **По образцу — переработать всю запись** — загрузите файл и опишите желаемые изменения. Ползунок сходства регулирует влияние структуры исходника: выше — ближе к образцу, ниже — больше свободы.
- **По образцу — изменить фрагмент** — укажите начало и конец участка от 3 до 90 секунд в пределах загруженной записи.

Поддерживаются WAV, MP3, FLAC, M4A, OGG, OPUS, AAC и WEBM, до 100 МБ,
длительность от 10 до 300 секунд. Сервер проверяет фактическое аудио через FFprobe
и преобразует его в рабочий WAV через FFmpeg. Загрузка идёт сразу в каталог музыки;
временное хранилище multipart для неё не используется.

В поле «Что изменить в образце» опишите правки, например: «Сохранить мелодию,
заменить ударные на мягкие, добавить акустическую гитару». В «Описание песни»
можно уточнить желаемое конечное звучание. Для конкретных слов укажите текст песни;
без него модель может изменить слова исходной записи. «Без вокала» просит инструментальный результат.

Длительность результата соответствует образцу. Музыкальное планирование и автоматическое
уточнение для этих режимов отключены. Исходник хранится отдельно и повторно доступен
при открытии задания из истории. Сохранение и удаление результата не удаляют исходник.
Это генеративная переработка: точность отдельных изменений зависит от модели.

Во время загрузки образца, генерации текста и аудио показывается `loading1.gif`.
Та же анимация обозначает поиск фотографий и видео по описанию; после завершения
или ошибки индикатор скрывается.

При запуске используется `scripts/music_runtime_fixes.py`: он освобождает GPU после
каждого задания и возвращает частично загруженные модели в RAM, если перенос на GPU
прервался ошибкой. Установщик копирует этот файл рядом с `start-music.ps1`.
Для PyTorch используется распределитель памяти `cudaMallocAsync`, уменьшающий
фрагментацию. Когда выключены Thinking и улучшение описания, скрытое планирование
метаданных через LM также отключено. Ошибка конкретного задания передаётся в облако;
нехватка VRAM показывается понятным сообщением.

## Проверки

```powershell
.\gradlew.bat test frontendTest
python scripts/test_music_runtime_fixes.py
node src/test/js/music-browser-smoke.cjs
```

Для проверки настоящей генерации через Java-клиент (10 секунд аудио, XL + LM 1.7B):

```powershell
$env:MUSIC_LIVE_TEST = 'true'
.\gradlew.bat test --tests ru.homeserver.photoshare.homeserver.music.MusicLiveTest
$env:MUSIC_LIVE_TEST = 'false'
```

Этот тест выключен при обычном запуске тестов. Его результаты и промпты сохраняются в `K:\muz_gen`.

Серверные тесты проверяют сохранение, удаление, историю, ошибки, запрет параллельных
генераций, протокол ACE-Step, ограничение адресов, авторизацию, CSRF и HTTP Range.
Браузерная проверка запускает настоящий Chromium с локальным тестовым музыкальным API
на ширине 1280 и 390 пикселей. Она не измеряет качество реальной музыкальной модели.
